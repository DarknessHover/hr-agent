# 公共求职者界面侦察文档 v0.3

> 状态：当前页面事实摘要
> 更新：2026-10-27
> 页面：BOSS招聘者端电子简历页

## 1. 页面识别

- 应用包名：`com.hpbr.bosszhipin`
- 已验证Activity：`com.hpbr.bosszhpin.boss.resume2.normal.BossViewGeekResumePagerActivity`
- 正文滚动容器：`view_pager / refresh_layout / rv_list`
- 底部动作区域：`cl_bottom_actions`

页面资源ID会在不同区块复用，因此解析必须依赖“区块标题 + 同区块相对位置”，不能全局按ID取值。

## 2. 当前采集模型

简历头部读取姓名、副标题、求职状态、活跃状态、工作年限、学历、年龄、个人优势和标签。求职期望读取职位、城市、薪资和行业。

可选内容区块包括：

- 工作经历
- 项目经历
- 教育经历
- 社团/组织经历
- 专业技能
- 所获荣誉
- 实习经历
- 资格证书
- 图片作品
- 视频作品
- 培训经历
- 志愿服务经历

不同候选人填写的区块集合和顺序均不固定。当前解析器将同一区块跨屏重复文本去重并按页面顺序拼接。

## 3. 折叠正文必须先展开

简历正文可能以三种形状折叠：

| 形状 | 可见标记 | 出现位置 |
|---|---|---|
| 头部正文后缀 | `...  查看全部` | `tv_geek_description`，即“个人优势” |
| 区块条目折叠 | `展开全部N个工作经历/资格证书/所获荣誉/项目经验` | 区块内的独立标记节点 |
| 作品区后缀 | `...  展开` | 图片作品、视频作品区 |

折叠段整体藏住技能与经历表述，因此**采集前必须展开**：技能类一票否决判据要求“简历中能否看到某技能”，基于残缺正文做出的否决不可复核。

展开落点按形状分别计算：

- 独立标记节点整块可点，取节点中心即生效。
- 正文后缀标记由 TextView 内的 ClickableSpan 处理，节点自身与祖先都不可点击；使用末行右侧 `(right-70, bottom-20)` 作为当前有效落点。

展开过程遵守公共页面守卫：每次点击后重新读屏，页面不是简历页或姓名漂移立即停机；可见文本形状未变化记 `fold_expand_no_effect`，两种受控触摸（120ms tap、200ms press）都无效时记 `fold_expand_stuck` 并继续采集，把残缺留在事件日志里，不因一次无效触摸停掉整轮。每屏最多展开四次，整体仍受 `max_scrolls` 上限约束。

## 4. 停止条件

- 读到“牛人分析器”时停止采集；该区块及其之后内容不入库。该区块内的“查看全部8项分析”不是折叠标记，不参与展开。
- 滑动后视图签名不变时判定真实触底。
- `max_scrolls` 只作为安全上限，不能作为正常截断条件。
- 滑动只能在已确认的简历滚动容器内执行。

## 5. 身份和动作栏

- 身份优先使用简历顶栏/正文姓名文本，不使用头像或性别图标推断。
- “立即沟通”：1号可发送入口，点击可能直接产生首次招呼。
- “立即联系牛人”：平台付费广告入口，走它联系候选人需额外付费，不属于本项目的招呼动作；1号命中即记 `aborted` 并跳过，不发送，也不记为已有会话（人工核验确认，2026-10-27）。
- “继续沟通”：已有会话，1号禁止再次发送。
- “已标记为不合适（点击取消）”：不自动取消，转人工复核。

不可逆动作前必须重新读取页面姓名和按钮，不复用采集开始时的坐标或文本。

## 6. 已知限制

- 性别和头像没有可靠文本，不采集、不推断。
- 平台稳定候选人ID当前不可见，组合指纹仍可能退化。
- 展开标记落在末行右侧是基于单次真机取证的定位；若BOSS改变折叠控件结构，`fold_expand_stuck` 事件会先出现，此时必须重新侦察而不是放宽判据。
- BOSS升级可能改变Activity、资源ID和控件层级；变更后必须重新侦察。

## 7. 证据纪律

正式运行不再为每一步长期保存XML/PNG。完整页面证据只在 `debug` 模式、异常、风险熔断、身份不一致或不可逆动作边界保存。进入测试的控件树必须脱敏。
