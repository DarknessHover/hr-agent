# 1号状态机数据库建表文档 v0.4

> 状态：当前兼容结构
> 更新：2026-10-27
> 数据库：`data/hr_agent_v2.sqlite3`
> DDL事实源：`data/schema.sql`（`user_version=3`）

## 1. 当前结构

当前 `candidate` 单表有49列，同时保存候选人身份、简历快照、Agent评估、首次招呼和证据引用。这是已经运行的兼容结构，不是长期目标；目标模型见ADR-0003。

| 组 | 列 |
|---|---|
| 身份 | `platform`、`platform_candidate_id`、`fingerprint`、`display_name` |
| 头部事实 | `age`、`work_status`、`active_status`、`work_years`、`degree`、`headline_subtitle`、`summary`、`tags` |
| 求职期望 | `expect_role`、`expect_city`、`expect_salary`、`expect_industry` |
| 可选区块 | `work_experience_text`、`project_experience_text`、`education_text`、`club_experience_text`、`skills_text`、`honors_text`、`internship_text`、`certificate_text`、`portfolio_image_text`、`portfolio_video_text`、`training_text`、`volunteer_text` |
| 首次招呼 | `greeting_phrase`、`greeting_state`、`greeting_planned_at`、`greeting_boundary_at`、`greeting_verified_at` |
| 评估 | `eval_job_profile_key`、`eval_job_profile_version`、`eval_score`、`eval_threshold`、`eval_decision`、`eval_reasons_text`、`eval_evaluated_at`、`eval_decision_source` |
| 采集 | `source_activity`、`capture_version`、`content_hash`、`raw_capture_json`、`evidence_json`、`first_seen_at`、`last_seen_at` |

## 2. 约束

- `fingerprint` 和 `content_hash` 可空且唯一。
- `greeting_state` 为 `pending/session_exists/sent/unknown/aborted`。
- `eval_decision` 可空，非空时为 `greet/do_not_greet/needs_review`。
- `display_name`、`first_seen_at` 和 `last_seen_at` 非空。

## 3. 写入规则

- 唯一写入口是 `app/store.py`。
- 重采只更新可见事实白名单和 `last_seen_at`，不得覆盖 `first_seen_at` 或招呼终态。
- 评语去除首尾空白后必须非空；100–300字仅为质量建议，超出范围仍保存原文。
- `sent/unknown/aborted` 不能改写为其它状态。
- “继续沟通”按业务规则记 `session_exists`，不发送。
- “已标记为不合适”转人工复核，不自动取消。
- 点击“立即沟通”后只有回读到送达才记 `sent`；不能确认记 `unknown`。

## 4. 当前局限

- 可选简历区块按列展开，平台新增区块需要改DDL。
- 简历、评估、业务动作和证据生命周期混在同一行。
- 姓名软匹配和组合指纹都不是稳定平台身份。
- `raw_capture_json/evidence_json` 仍包含过量兼容信息。

这些问题由ADR-0003解决；迁移完成前不得删除现有列或覆盖运行库。

## 5. 数据保护

数据库包含候选人个人信息并以本地明文保存。不得上传、共享或用于未脱敏测试。正式数据删除、保留期和加密策略仍需业务负责人确认。
