# 2号状态机数据库建表文档 v0.5

> 状态：当前兼容结构
> 更新：2026-10-27
> 数据库：`data/reply_agent.sqlite3`
> DDL事实源：`data/schema.sql`、`data/reply_schema.sql`

## 1. 建库顺序

2号数据库先执行 `data/schema.sql` 创建兼容 `candidate` 表，再执行 `data/reply_schema.sql` 创建四张回复专属表：

1. `reply_conversation`
2. `inbound_message`
3. `reply_action`
4. `reply_send_attempt`

`candidate.greeting_*` 是复用1号DDL带入的兼容列，2号不得读写这些列作为业务状态。目标结构和迁移约束见ADR-0003。

## 2. `candidate`

当前保存点击会话时创建的候选人占位，以及随后采集的简历快照。2号不写 `fingerprint` 和 `content_hash`，不以候选人级指纹做业务幂等。

当前兼容表仍包含：

- 身份及头部字段；
- 求职期望；
- 多个可选简历区块TEXT列；
- 1号专属 `greeting_*`；
- 兼容 `eval_*`；
- 原始采集与证据路径字段。

这些字段是过渡实现，不代表长期模型。2号真正的动作状态只存在回复专属表中。

## 3. `reply_conversation`

| 列 | 约束 | 语义 |
|---|---|---|
| `id` | INTEGER PK | 会话主键 |
| `candidate_id` | FK，CASCADE | 关联候选人占位 |
| `platform` | NOT NULL | 当前为 `boss_zhipin` |
| `platform_conversation_id` | 可空 | 平台稳定ID，UI不可得时为空 |
| `conversation_fingerprint` | UNIQUE NOT NULL | 组合会话指纹，不得仅用姓名 |
| `list_display_name` | NOT NULL | 列表显示姓名 |
| `job_title` | 可空 | 列表职位原文 |
| `unread_count_before_open` | 可空 | 未读数量，仅观测 |
| `unread_signal` | 可空 | 未读控件信号 |
| `source_activity` | 可空 | 列表页面Activity |
| `evidence_json` | 可空 | 当前兼容证据引用，后续收敛 |
| `first_seen_at/last_seen_at` | NOT NULL | 首次和最近观察时间 |

## 4. `inbound_message`

| 列 | 约束 | 语义 |
|---|---|---|
| `id` | INTEGER PK | 入站消息主键 |
| `conversation_id` | FK，CASCADE | 所属会话 |
| `platform_message_id` | 可空 | 平台消息ID |
| `message_fingerprint` | UNIQUE NOT NULL | 会话、时间、正文和方向形成的消息指纹 |
| `visible_time_text` | 可空 | UI可见时间原文 |
| `body_text` | NOT NULL | 可证明为入站的文本正文 |
| `direction` | CHECK=`inbound` | 防止把己方消息作为待回复消息 |
| `evidence_json` | 可空 | 当前兼容证据引用 |
| `observed_at` | NOT NULL | 观察时间 |

## 5. `reply_action`

| 列 | 约束 | 语义 |
|---|---|---|
| `id` | INTEGER PK | 动作主键 |
| `conversation_id` | FK，CASCADE | 所属会话 |
| `inbound_message_id` | FK UNIQUE，CASCADE | 每条入站消息最多一个动作 |
| `idempotency_key` | UNIQUE NOT NULL | `sha256("reply:" + message_fingerprint)` |
| `profile_key/profile_version` | 可空 | 岗位画像版本 |
| `decision` | CHECK | `request_resume/reject/needs_review`；当前作为兼容粗分类，精确回复意图由 `phrase_key` 表达 |
| `decision_reason` | NOT NULL | 去除首尾空白后非空；建议100–300字，超出仍保存原文 |
| `phrase_key/phrase_text` | 可空 | 发送前绑定的允许话术 |
| `state` | CHECK | `planned/pending/sent/unknown/needs_review` |
| `planned_at` | NOT NULL | 计划时间 |
| `send_boundary_at/verified_at` | 可空 | 越界和确认时间 |
| `evidence_json` | 可空 | 当前兼容证据引用 |

`idempotency_key` 不包含话术键，避免通过更换话术绕过同一消息的发送边界。

动作状态规则：

- `send` 建立为 `planned`：拒绝意图写 `reject`，其它允许话术写兼容值 `request_resume`；`begin_send` 复核话术键、逐字正文和兼容分类后进入 `pending`；
- `review` 建立为 `decision=needs_review/state=needs_review`，不得绑定话术；
- `begin_send`、发送入口、人工重试和人工发送追认都会拒绝 `needs_review`；
- `sent/unknown` 记录真实发送结果，不因后续策略调整覆盖。

## 6. `reply_send_attempt`

该表记录不可逆发送的最小安全审计，不是测试流水。

| 列 | 约束 | 语义 |
|---|---|---|
| `id` | INTEGER PK | 尝试主键 |
| `reply_action_id` | FK，CASCADE | 所属动作 |
| `attempt_no` | UNIQUE组合、>=1 | 动作内尝试序号 |
| `phrase_key/phrase_text` | NOT NULL | 当次逐字绑定话术 |
| `state` | CHECK | `pending/sent/unknown` |
| `send_boundary_at` | NOT NULL | 当次越界时间 |
| `verified_at` | 可空 | 确认时间 |
| `resolution_note` | 可空 | 人工追认或重试原因 |
| `retry_authorized_at` | 可空 | 有无效证据后的授权时间 |
| `evidence_json` | 可空 | 当前兼容证据引用 |

未来可删除逐步XML/PNG引用，但必须保留尝试序号、越界时间和终态，防止不安全重发。

## 7. 外键和删除

```text
candidate
└─ reply_conversation
   ├─ inbound_message
   │  └─ reply_action
   │     └─ reply_send_attempt
   └─ reply_action
```

外键使用 `ON DELETE CASCADE`。正式候选人数据删除必须获得明确授权，并在删除前记录表计数、删除后执行外键检查。

## 8. 当前限制与迁移方向

- 2号库仍携带1号无意义的 `greeting_*` 列。
- 简历可选区块按列展开，平台新增区块会推动DDL变化。
- `eval_*` 与2号动作决策重复。
- `raw_capture_json/evidence_json` 混合了业务快照和调试证据。
- `decision` 是历史兼容粗分类，不适合按意图查询；一般语境回复应使用 `phrase_key` 关联允许话术目录。本次逻辑调整不改变表结构。
- 2026-10-26 以前创建的正式库，其SQLite表级CHECK仍可能包含旧的 `aborted` 允许值；当前代码不再写入该值。历史 `needs_review + sent/unknown` 行保留为真实运行事实，不在本阶段改写。

ADR-0003确定的目标是：稳定候选人身份、JSON简历快照和业务动作分离。迁移完成前，本文件只描述当前真实结构。
