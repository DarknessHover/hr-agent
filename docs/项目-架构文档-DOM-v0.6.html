HR 招聘 Agent · 当前架构

总览模块数据CLI契约

01 · Current boundary

两套业务编排，共享一组底层能力

实现事实源为当前 app/ 与 data/*.sql；本机设备绑定和业务配置分别遵循 .env.example 与 config/*.example.yaml 的接口。1号、2号共享设备、页面和简历能力，但不共享动作状态、幂等或恢复策略。

验证边界：2号已实现Agent从完整允许清单按语境选话术并通过离线测试，但尚未恢复真机验收；ADR-0003数据模型也尚未迁移。

02 · Module ownership

模块职责

层模块负责不负责
入口cli.py命令路由、证据等级业务授权
本机设置settings.py读取.env与系统环境变量，形成准入设备契约业务配置与设备动作
公共设备device.pyADB和输入原语页面与候选人语义
公共页面resume.py、screen_ops.py控件树、页面分类、熔断和导航守卫动作终态
公共采集resume.py:fold_targets、resume_collector.py逐屏识别并展开折叠正文、简历多屏拼接是否发送
公共评语规则review.py非空硬约束；100–300字建议，超范围不阻断入库业务决策
1号main.py、walker.py、store.py牛人列表、评估、首次招呼消息级回复
公共回复契约reply_plan.py校验允许话术目录并表达send/hold、话术键、意图和理由页面动作与发送授权
2号reply_ui.py、reply_flow.py、reply_main.py、reply_store.py首次新招呼、按语境选择允许话术、人工挂起和恢复已有交流的多轮跟进

03 · Data boundary

当前数据边界

1号数据库

当前单表同时保存简历、评估和首次招呼。重采只更新可见事实，终态封口。

2号数据库

兼容candidate表之外，包含会话、入站消息、回复动作和发送尝试四层。

不可跨库同步

两套状态机不得按姓名复制动作状态；姓名不是稳定平台身份。

3号准备度

ReplyPlan、消息方向、话术定位、发送边界和回读可复用；仅沟通列表与消息意图策略尚未实现。

04 · CLI contract

标准入口

python -m app doctor
python -m app [--evidence off|minimal|debug] state1 COMMAND ...
python -m app [--evidence off|minimal|debug] state2 COMMAND ...
python -m app debug state1|state2 COMMAND ...

旧的 python -m app.main 与 python -m app.reply_main 是兼容入口。进程退出0只表示命令正常收敛，不等于消息已发送；业务结果必须读取数据库状态和事件日志。

05 · Safety contracts

跨模块不可绕过的契约

页面未知即停机

不盲点、不盲返；命中验证码或风控同样熔断。

坐标不能跨观察复用

不可逆动作前重新读屏并绑定目标控件。

分流与幂等

2号采用平台“新招呼”列表分流；数据库按当前入站消息阻止重复越界。

Agent无设备副作用

判断失败或重做不会直接点击平台。
