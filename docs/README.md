## 数据结构事实层级

1. 数据库建表文档定义经人工审定的逻辑结构契约。
2. `data/*.sql` 是SQLite可执行DDL。
3. 实际 `.sqlite3` 文件是当前运行时物理事实。
4. 迁移文档和脚本负责从旧物理结构转换到新契约；修改建表文档或SQL不会自动改变现有数据库。

出现不一致时不得静默覆盖：建表文档表示目标结构，SQL表示新建行为，现有库表示当前事实。

## 维护规则

1. 需求写目标行为；开发文档写当前代码和明确偏差；建表文档写逻辑DDL；ADR只保留长期取舍理由；实测记录只保存可复核的工程结论。
2. 每个主题只保留一个现行版本。升级后删除旧文件并修复全部引用，不另建长期归档目录。
3. 字段、类型、可空性、默认值、主外键、唯一约束、索引和迁移要求必须在建表文档中无歧义；SQL和测试据此实现。
4. 批次姓名、触摸流水、临时成功率和逐步XML/PNG不进入需求或开发文档。长期测试夹具必须脱敏。
5. 当前默认只进行离线验证。真机自动化测试恢复前必须由需求方明确授权，并设定单次运行预算和人工停止条件。
6. 文档只引用仓库相对路径；移动或删除文件后必须检查链接、图表和旧术语。
7. 小幅文字修正不升版本；需求语义、接口、数据结构或关键流程变化必须升版本并记录。
8. 候选人数据、运行日志、截图、数据库、真实业务配置和本机 `.env` 不得上传代码仓库；仓库只保留 `.env.example` 与脱敏的 `config/*.example.yaml`。
