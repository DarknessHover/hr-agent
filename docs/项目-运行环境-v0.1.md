# 项目运行环境 v0.1

> 状态：现行
> 更新日期：2026-10-29
> 适用范围：1号状态机、2号状态机及公共能力；不包含3号状态机设计

## 1. 环境基线

| 项目 | 当前契约 |
|---|---|
| 主机系统 | Windows；其他系统尚未验证 |
| Python | 3.12 或更高版本 |
| Python 运行时依赖 | 仅标准库，`pyproject.toml` 中 `dependencies = []` |
| Conda 环境 | 根目录 `environment.yml`，环境名 `hr-agent` |
| 外部工具 | Android SDK Platform Tools（ADB） |
| 目标应用 | BOSS 直聘，包名 `com.hpbr.bosszhipin` |
| 工作目录 | 项目根目录；所有示例均从根目录运行 |

项目直接以源码运行，不要求先安装 Python 包：

```powershell
conda env create -f environment.yml
conda activate hr-agent
python -m app --help
```

`environment.yml` 固定解释器版本，并通过 `pip -e .` 安装当前源码；`pyproject.toml` 声明项目自身的 Python 依赖。两者职责不同，增加第三方包时只在 `pyproject.toml` 中维护依赖，再执行 `conda env update -f environment.yml --prune` 更新环境，不手工复制两份版本清单。

不使用 Conda 时，也可以建立标准虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
```

`pip install -e .` 只用于提供标准的可编辑安装元数据；程序读取的 `config/`、`data/` 和 `log/` 仍位于源码项目根目录，因此不要把当前版本当作可脱离仓库运行的发行包。首次安装构建工具可能需要访问 Python 包索引。日常本地运行无需安装项目，也无需执行依赖下载。

## 2. Python 依赖管理

`pyproject.toml` 是 Python 版本和包依赖的唯一机器可读事实源。当前没有 `requirements.txt`，也不引入 PyYAML、pytest 或 ORM：

- `config/reply_phrases.yaml` 的内容是 JSON 兼容格式，由标准库 `json` 读取；
- 数据库使用标准库 `sqlite3`；
- 测试使用标准库 `unittest`；
- ADB 通过标准库 `subprocess` 调用。

以后增加或移除第三方包时，应先修改 `pyproject.toml`，再同步本文的依赖边界；不要另建一份手工版本清单。

## 3. 本机环境变量与 ADB 路径

根目录 `.env` 保存本机 ADB 路径和唯一准入设备身份；该文件不入仓，仓库只保留 `.env.example`。系统环境变量优先于 `.env`。必需变量为：

- `HR_AGENT_ADB_PATH`
- `HR_AGENT_DEVICE_SERIAL`
- `HR_AGENT_DEVICE_MANUFACTURER`
- `HR_AGENT_DEVICE_MODEL`
- `HR_AGENT_DEVICE_CODENAME`

首次配置：

```powershell
Copy-Item .env.example .env
```

`.env` 由 `app/settings.py` 使用标准库读取，只支持注释、可选 `export` 前缀和简单 `KEY=VALUE`；它不会执行文件中的命令或 shell 表达式。缺少任一必需变量时，程序在接触ADB前拒绝继续。

安装 Android SDK Platform Tools 后，将 `HR_AGENT_ADB_PATH` 指向 `adb.exe`。1号状态机也可通过 `--adb` 临时覆盖该路径，但不会覆盖准入设备身份。

检查命令：

```powershell
adb version
adb devices
```

标准入口可写为 `python -m app doctor`；临时覆盖1号 ADB 路径可写为 `python -m app state1 --adb D:\Android\platform-tools\adb.exe selfcheck`。2号状态机统一读取 `.env` 或系统环境变量。

## 4. 固定设备准入

设备层只允许操作 `.env` 或系统环境变量声明的设备，任一身份字段不一致都会拒绝继续：

| 字段 | 允许值 |
|---|---|
| ADB serial | `HR_AGENT_DEVICE_SERIAL` |
| manufacturer | `HR_AGENT_DEVICE_MANUFACTURER` |
| model | `HR_AGENT_DEVICE_MODEL` |
| device | `HR_AGENT_DEVICE_CODENAME` |
| ADB state | `device` |

连接检查：

1. 在手机“开发者选项”中开启 USB 调试；
2. 使用数据线连接电脑，在手机端接受该电脑的调试授权；
3. 执行 `adb devices`，确认唯一目标设备显示为 `device`，而非 `unauthorized` 或 `offline`；
4. 执行 `python -m app doctor` 完成身份和安装包校验。

设备更换不是普通配置变更。必须重新核验分辨率、页面结构、点击行为与风险边界，并在本机更新环境变量；不得把真实设备标识写回源码或文档。

## 5. BOSS 直聘和页面准备

目标包名固定为 `com.hpbr.bosszhipin`。运行前应确认：

- 应用已经安装并完成 HR 账号登录；
- 没有遮挡业务页面的系统弹窗、权限弹窗、升级提示或风控提示；
- BOSS 位于前台；
- 1号命令从候选人列表或目标简历页开始；
- 2号列表命令从“新招呼”列表开始，聊天相关命令从对应会话上下文开始。

`doctor` 校验设备身份和安装包，并记录1号建表文件是否存在；当前不会因建表文件缺失单独返回失败。它不确认登录态、前台页面或当前页面类型。页面未知、身份无法确认或出现风险信号时，程序应停机留证，不通过猜测点击恢复。

## 6. 必需配置

| 路径 | 用途 | 维护要求 |
|---|---|---|
| `config/job_profiles.yaml` | 岗位画像和候选人判断依据 | 由脱敏示例复制；真实文件不入仓；修改筛选标准时同步评估规则和文档 |
| `config/reply_phrases.yaml` | 公共允许话术清单 | 由脱敏示例复制；真实文件不入仓；键、意图和正文必须完整且正文须与真机逐字一致 |

业务配置不从环境变量注入。仓库中的 `config/*.example.yaml` 仅描述脱敏结构并供离线测试使用；运行前应通过受控渠道取得真实配置，并确认其适用于当前岗位和账号。

根目录 `.gitignore` 是仓库边界的机器可读事实源：提交 `.env.example`、`config/*.example.yaml` 和 `data/*.sql`；屏蔽本机 `.env`、真实 `config/*.yaml`、SQLite运行库及其sidecar、`log/`、`recon/`、`tmp/` 和受保护素材区。正常 `git add .` 不应纳入这些本地内容。

## 7. 数据库、日志与证据

### 7.1 数据库

| 流程 | 数据库 | 建表事实源 |
|---|---|---|
| 1号状态机 | `data/hr_agent_v2.sqlite3` | `data/schema.sql` |
| 2号状态机 | `data/reply_agent.sqlite3` | 先执行 `data/schema.sql`，再执行 `data/reply_schema.sql` |

数据库包含候选人事实、简历快照、判断结果和动作状态。正式库不用于保存逐步 XML 操作树。

备份或迁移前必须停止程序。若数据库旁存在同名 `-wal`、`-shm` 文件，应和主数据库作为同一组处理；不要只复制正在写入的 `.sqlite3` 文件。覆盖或迁移正式库前，应另建可恢复备份并先在副本验证。

### 7.2 运行日志

每次执行命令都会创建独立运行目录：

```text
log/
├─ proactive_greeting/<run_id>/
└─ reply_new_greetings/<run_id>/
```

每个运行目录包含 `events.jsonl`、`run.log` 和 `evidence/`。事件日志用于回溯状态和动作；它不是业务数据库，也不应无限期积累。

### 7.3 证据等级

| 等级 | XML/PNG 策略 | 适用场景 |
|---|---|---|
| `off` | 不保存 | 明确不需要页面证据的低风险检查 |
| `minimal` | 只在关键边界、异常或风险场景保存 | 正式运行默认值 |
| `debug` | 保存流程请求的完整证据 | 页面适配、故障复现和短期实机调试 |

事件日志在三个等级下都保留。可在标准入口的状态机名称之前指定等级：

```powershell
python -m app --evidence off state1 scan-list
python -m app --evidence minimal state2 scan
python -m app --evidence debug state2 inspect-phrases --conversation-id 12
```

## 8. 命令入口

```powershell
python -m app doctor
python -m app state1 COMMAND [参数]
python -m app state2 COMMAND [参数]
python -m app debug state1 COMMAND [参数]
python -m app debug state2 COMMAND [参数]
```

完整参数以CLI帮助为准：

```powershell
python -m app --help
python -m app state1 --help
python -m app state2 --help
```

1号 `run` 和2号 `run-one/run-page` 默认dry-run；`greet` 与 `send-planned` 是显式发送命令。当前真机自动化已暂停，以上入口只用于帮助检查、离线测试或未来恢复后的受控运行。`app.main` 和 `app.reply_main` 仅保留为兼容入口。

## 10. 常见故障

### PowerShell 无法识别 conda

优先在 Anaconda Prompt 中执行环境创建命令，或执行 `conda init powershell` 后重新打开 PowerShell。先用 `conda --version` 确认当前终端能够调用 Conda，再运行 `conda env create -f environment.yml`。

### 找不到 Python

执行 `python --version`。若 Windows 命中了不可用的应用商店别名，安装 Python 3.12+ 并在安装器中启用 PATH，或使用 `py -3.12` 代替文档中的 `python`。

### 找不到 ADB

执行 `adb version` 并检查 `platform-tools`，再确认 `HR_AGENT_ADB_PATH` 指向实际存在的 `adb.exe`。2号状态机和 `doctor` 读取系统环境变量或根目录 `.env`；1号还可通过 `--adb` 临时覆盖路径。

### 设备显示 unauthorized 或 offline

重新插拔数据线，保持手机解锁，撤销并重新接受 USB 调试授权，然后再次执行 `adb devices`。状态恢复为 `device` 前不要运行状态机。

### 设备 serial 或身份不匹配

不要临时篡改 `.env` 绕过校验。先确认连接的是否为项目准入设备；如确需换机，按设备变更重新完成实机验证，再更新本机环境变量。

### BOSS 未安装、未登录或不在前台

确认包名可被 ADB 查询，手工打开 BOSS 并完成登录，再把页面定位到命令要求的入口。不要依赖自动点击穿过登录、升级或风控页面。

### 页面被识别为 unknown 或出现风险信号

停止运行并查看本次 `run.log`、`events.jsonl` 和关键证据。需要复现时改用 `--evidence debug` 执行最小范围的只读命令；在页面规则未更新前不要扩大操作批次。

### Windows 临时目录无写入权限

为当前 PowerShell 会话指定项目内临时目录后重试离线测试：

```powershell
New-Item -ItemType Directory -Force .\tmp | Out-Null
$env:TEMP = (Resolve-Path .\tmp).Path
$env:TMP = $env:TEMP
python -m unittest discover -s tests -v
```

## 11. 安全与隐私

- 数据库、日志、XML 和截图可能含姓名、履历、聊天内容及联系方式，均按个人信息处理。
- 本机 `.env` 和真实业务配置不入仓；只提交不含实际设备标识和业务话术的示例文件。
- 调试材料只保留到问题定位完成；进入长期测试夹具、文档或截图前必须脱敏。
- 不把正式数据库、运行日志和真机截图提交到公开仓库或发送给无关人员。
- 不用批次姓名、点击流水或完整 XML 扩充现行文档；只沉淀已经验证的稳定规则。
- 发送结果不明确时保持 `unknown` 并转人工处理，不能用重复发送来探测状态。
