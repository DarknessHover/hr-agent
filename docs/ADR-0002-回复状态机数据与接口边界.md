# ADR-0002：回复状态机的数据、幂等与接口边界

- **状态**：已接受并实施；通用话术选择已完成离线实现
- **日期**：2026-10-20
- **最后同步**：2026-10-27
- **关联**：[`ADR-0001`](ADR-0001-提骨架与参数化重构.md)、[`2号需求`](2号状态机-需求文档-v0.5.md)

## 背景

1号主动招呼和2号回复新招呼共享底层能力，但入口、动作语义、幂等和恢复不同。混用动作状态或仅按姓名跨流程同步，会放大误发和重复回复风险。

## 决策

- 1号使用 `data/hr_agent_v2.sqlite3`，2号使用 `data/reply_agent.sqlite3`；不按姓名跨库同步动作终态。
- 1号的幂等单位是候选人首次招呼；2号的幂等单位是当前入站消息。
- 2号以 `message_fingerprint`、`inbound_message_id` 和 `idempotency_key` 唯一约束阻止重复越界；话术键不得进入幂等键。
- `ReplyPlan` 只表达 `send/hold`、业务决策、允许话术键和理由；页面适配器不授权发送，仓储不读取页面。
- 发送前绑定当前会话、消息和逐字话术；发送后只凭可观察气泡或送达证据写 `sent`，不明写 `unknown`。
- `needs_review` 是不可发送状态；重试必须先证明上一跳没有生效。
- 日志与证据不代替数据库幂等；正常业务库不保存逐步XML、PNG和触摸流水。

## 策略归属

本ADR不规定2号必须使用哪些具体常用语。2026-10-27以前的固定出口已被 `send/hold + phrase_key + reason` 取代；地址确认只是无其它问题时的策略优先项。话术选择规则以2号需求文档为准，兼容存储值以2号数据库文档为准。

## 后果

动作状态可以独立审计，公共执行能力可供后续状态机复用。代价是同一候选人可能在两个数据库各有快照，稳定平台身份不可得时不做冒险合并。
