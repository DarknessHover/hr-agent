# HR 端招聘 Agent 开发文档 v0.6

> 状态：当前实现说明；不把目标需求写成已实现事实
> 更新：2026-10-29

## 1. 代码结构

项目是PC侧单进程Python程序，通过ADB控制本机环境声明的唯一准入Android设备。

```text
公共层
  settings.py            读取本机.env和准入设备身份；系统环境变量优先
  device.py              ADB、设备身份和输入原语
  resume.py              控件树、简历解析和页面识别
  screen_ops.py          页面注册、熔断、等待与导航守卫
  resume_collector.py    折叠正文展开和多屏简历采集
  review.py              评语非空校验与长度建议
  logging.py             分区日志与按需证据

1号
  walker.py + main.py + store.py

2号
  reply_ui.py + reply_plan.py + reply_flow.py
  + reply_main.py + reply_store.py

入口
  cli.py + __main__.py
```

`settings.py` 只解析简单 `KEY=VALUE`，不执行 shell 内容。缺少任一设备变量时，`Device` 在接触ADB前拒绝继续；1号 `--adb` 只能覆盖可执行文件路径，不能覆盖准入设备身份。

公共层不理解“主动招呼”或“回复新招呼”，也不授权发送。1号、2号分别拥有业务编排、幂等、终态和恢复路径。`ReplyPlan` 只表达 `send/hold`、决策、话术键和理由。

简历折叠识别位于 `resume.py:fold_targets`，展开位于 `resume_collector.py:expand_folded`，1号和2号共同调用 `collect_resume`，没有状态机专用副本。

## 2. 1号当前链路

```text
确认牛人列表 → 顺序选卡 → 进入简历 → 展开并多屏采集 → 落盘
→ 外部Agent写评估 → 身份/终态/按钮硬闸
→ greet时发送并回读；其它决策返回列表
```

1号以候选人的首次招呼为幂等单位。`sent/unknown/session_exists` 阻止再次自动触达；评语只硬校验非空，100–300字为非阻断建议。

## 3. 2号当前链路

```text
从“新招呼”打开会话 → 校验身份和当前入站消息
→ 保存消息并采集简历
→ Agent提交 send/hold、phrase_key和理由
→ hold挂起；send校验完整允许清单并绑定逐字话术
→ 发送前重校验 → 发送 → 回读气泡
→ sent时验证目标已离开“新招呼”
```

`reply_plan.py` 统一加载并校验 `config/reply_phrases.yaml`，不再维护固定outcome映射。`reply_flow.py` 接收 `action/phrase_key/comment`；`reply_main.py` 与 `reply_store.py` 分别在发送入口和仓储阶段复核允许键、正文、兼容决策分类和消息绑定。

地址确认 `p14_address_acceptance` 仅作为Agent在“无其它问题且地点尚未确认”时的默认策略提示。代码不会阻止Agent选择工作时间、福利、能力核验等其它已核验话术；没有安全匹配时使用 `hold`。

## 4. 兼容存储语义

现有 `reply_action.decision` CHECK保持不变：

- `request_resume`：所有非拒绝发送的兼容分类；
- `reject`：`intent=reject` 话术；
- `needs_review`：`hold`，不可发送。

精确意图由 `phrase_key/phrase_text` 表达。该方案无需覆盖正式库，也保留历史记录可读性；未来ADR-0003迁移时可以再把兼容字段更名为通用动作语义。

## 5. 数据、证据和入口

- 1号数据库：`data/hr_agent_v2.sqlite3`；建表契约见1号数据库文档。
- 2号数据库：`data/reply_agent.sqlite3`；建表契约见2号数据库文档。
- 当前兼容结构仍混有候选人、简历和业务字段；目标拆分理由见ADR-0003。
- 默认 `minimal` 证据，只在不可逆边界、异常、风控和停机时保存XML/PNG；`debug`用于侦察，`off`用于离线或纯数据库命令。
- 本机 `.env`、真实 `config/*.yaml`、运行库和日志不入仓；只提交 `.env.example`、脱敏 `config/*.example.yaml` 与 `data/*.sql`。

标准入口：

```text
python -m app doctor
python -m app state1 ...
python -m app state2 ...
python -m app debug state1|state2 ...
```

`app.main` 和 `app.reply_main` 仅作为兼容入口。进程退出0不等于消息已发送，业务结果以数据库终态和事件日志为准。

## 6. 当前验证边界

2026-10-29以Python 3.12执行的58项离线测试全部通过。覆盖范围包括环境变量解析与缺失值封口、CLI路由、页面识别、折叠简历展开、评语软约束、脱敏允许话术选择、`hold`硬闸、逐字话术绑定、幂等、发送尝试和日志分区。测试通过 `tests/_config.py` 强制使用 `config/reply_phrases.example.yaml`，不读取真实业务话术。

2026-10-27账号状态异常后，真机自动化测试暂停；工程结论见 `docs/项目-实测记录-v0.1.md`。

在恢复真机条件前，可以验证纯函数、数据库、CLI路由和脱敏控件树；不能据此确认真实页面、话术面板、发送动作或平台风控下的稳定性。

## 7. 已知限制

- 平台稳定候选人ID、会话ID和消息ID在UI中不可得，当前使用组合指纹。
- 1号按姓名预跳过可能误伤同名候选人；昵称与简历实名不一致时只能转人工。
- 2号通用话术选择已完成离线实现，但尚未真机验证完整话术面板和发送链路。
- 现有SQLite为本地明文，保留期和加密策略尚未确定。
- ADR-0003目标数据模型尚未迁移。
- 页面结构依赖某招聘平台的当前版本，且目前无法进行真机复核。
