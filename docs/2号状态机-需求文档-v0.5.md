# 2号状态机需求文档 v0.5

> 状态：现行需求；通用话术选择已完成离线实现，真机待验
> 更新：2026-10-27
> 范围：处理 BOSS 直聘“新招呼”列表中的首次入站会话

## 1. 目标与边界

2号只处理平台已归入“新招呼”的会话。程序打开目标会话，确认当前待回复消息来自候选人，读取简历和可见聊天语境，再由Agent从 `config/reply_phrases.yaml` 中选择回复或挂起人工。

范围外：自由生成聊天文本、离开“新招呼”持续跟进历史会话、自动安排面试或Offer、拉黑、举报、删除会话，以及任何规避平台风控的行为。

## 2. 决策规则

Agent的输入包括当前候选人消息、可见语境、简历、岗位画像和允许话术清单。输出必须是以下之一：

- `send`：选择一个已核验 `phrase_key`，并给出非空理由。
- `hold`：没有安全匹配、语义不确定或需要人工判断，不绑定话术。

选择优先级：

1. 候选人提出明确问题时，优先选择直接回应该问题的允许话术。
2. 没有实质聊天背景或其它问题，且候选人基本符合岗位时，优先询问工作地点是否可以接受。
3. 候选人已经明确接受地点时，不重复询问；应选择下一条与语境匹配的话术。
4. 候选人明显不符合岗位时，可以选择允许清单中的婉拒话术。
5. 清单中没有语义匹配项时必须 `hold`，不得拼接、改写或输入自由文本。

评语去除首尾空白后必须非空；100–300字是非阻断质量建议。

## 3. 目标流程

```text
确认“新招呼”列表并重新定位会话
→ 打开聊天，校验身份和当前入站消息
→ 保存入站消息，采集并落盘简历
→ Agent分析语境与简历
→ send：从完整允许清单选择一个phrase_key
→ hold：写入人工挂起，不发送
→ 发送前重校验会话、消息、话术正文和发送控件
→ 发送并回读逐字一致的右侧气泡
→ 保存sent或unknown
→ sent时确认目标已离开“新招呼”列表
```

## 4. 安全与幂等

- 会话卡片和所有发送控件必须在动作前重新读取，不复用旧坐标。
- 会话指纹不得只使用姓名；消息指纹不得包含所选话术。
- 同一入站消息最多建立一个回复动作；更换话术不能绕过幂等键。
- 常用语正文必须同时在本地允许清单和当前真机面板逐字命中。
- 只有回读到目标右侧气泡才记 `sent`；越界后不明记 `unknown`。
- 自动重试必须先证明目标话术没有出站；无完整证据不得重发。
- 身份、方向、正文、话术、页面或发送结果不明时停止或挂起。
- 命中验证码、操作频繁、系统异常或未知页面时立即熔断。

## 5. 当前接口

单条和批量决策统一提交：

```json
{
  "脱敏候选人": {
    "action": "send",
    "phrase_key": "p09_work_schedule",
    "comment": "候选人询问工作时间，选择对应常用语"
  }
}
```

`hold` 不得包含 `phrase_key`；`send` 必须提供配置中唯一存在的键。代码会在规划、发送入口和仓储绑定阶段校验允许键及逐字正文。

数据库 `decision` 继续使用兼容值：拒绝意图写 `reject`，其它发送写 `request_resume`，挂起写 `needs_review`。精确回复意图由已保存的 `phrase_key/phrase_text` 表达，因此本次无需迁移现有正式库。

## 6. 验收条件

离线阶段已经覆盖：完整允许清单选择、未知键拒绝、`hold`禁止绑定话术、逐字正文校验、幂等和状态封口。以下结论必须等待真机条件恢复：完整话术面板可定位性、真实发送回读、列表迁移行为和平台风控下的稳定性。

2026-10-27封号事故不能证明某个具体时长或动作量是安全阈值；恢复真机测试前必须制定单次预算和人工停止条件，且不得通过规避风控继续运行。
