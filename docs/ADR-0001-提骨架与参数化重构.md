# ADR-0001：提取公共骨架并采用组合式复用

- **状态**：已实施
- **日期**：2026-10-16
- **最后同步**：2026-10-27
- **关联**：`docs/项目-开发文档-v0.6.md`

## 背景

1号和2号都需要设备控制、页面判断、简历采集和安全守卫，但列表入口、业务状态、幂等单位和恢复路径不同。复制整套状态机或用继承强行统一，都会把业务差异带入公共层。

## 决策

- 抽取 `device.py`、`resume.py`、`screen_ops.py`、`resume_collector.py`、`review.py` 和 `logging.py` 作为公共能力。
- `page_kind` 使用可扩展识别注册表；选择器和交互节奏通过参数注入。
- 1号用 `ListWalker` 复用顺序遍历；2号保留独立的“列表→聊天→简历→聊天”编排。
- 通过小接口和依赖注入组合能力，不让2号继承1号，也不复制公共实现。

## 理由与后果

公共修复只维护一份，同时避免两套状态机共享业务终态。代价是模块调用层次增加，接口边界必须由开发文档和测试持续约束。

该重构已经落地；当前模块职责以开发文档为准，本ADR不再维护实施流水或真机待办。
